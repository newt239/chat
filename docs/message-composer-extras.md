# 位置情報・録音・下書き・予約送信の設計

入力欄から送れる内容（位置情報・録音）と、送る前の状態（下書き・予約）をサーバーで持つための設計。

## 送れる内容

- メッセージは本文・添付・位置情報のどれか 1 つがあれば送れる。本文は空でもよい（`CreateMessageRequest` の CEL ルールと、ユースケースの `ErrEmptyMessage` で確かめる）。
  - 添付だけ・位置情報だけのメッセージを作れるようにするため、`message.body` の `NotEmpty` をやめた。

## 位置情報

- 緯度・経度・精度（メートル）・任意のラベルを `message` の列（`location_*`）に持つ。1 件のメッセージに位置情報は 1 つだけなので、別テーブルにしない。緯度と経度は必ずそろって入る。
- 入力欄のボタンで Geolocation API から現在地を 1 回取得し、地図で確かめてから添える。取得に失敗したら理由を出して取り直せる。
- 地図は Leaflet（react-leaflet）と OpenStreetMap のタイル。
  - Leaflet の CSS（`leaflet/dist/leaflet.css`）は地図の部品からだけ読み込む。トークンのユーティリティだけで書くという規約の例外。
  - Leaflet の z-index がダイアログなどの上に出ないよう、地図の要素を `isolate` にする。
  - 目印と誤差の円はトークンの色（`fill-accent` など）を SVG の class で付ける。
- 「地図アプリで開く」リンクは Google マップの検索 URL にする。モバイルでは地図アプリが開く。
- 検索では `has:location` で絞り込める。Meilisearch の文書の `has` に `location` を入れる（`has` は前から絞り込みに使える属性なので、設定は変えない）。

## 録音

- MediaRecorder で録音する。マイクの取得から試聴用 URL の解放まで、入力欄の中の録音部品の中で完結させる。止めたら試聴し、添付するか破棄する。
- 録音形式は `audio/webm;codecs=opus` → `audio/mp4` → `audio/aac` → `audio/ogg` の順に、対応しているものを選ぶ。iOS Safari は mp4（AAC）になる。
- 添付するファイルの MIME からはコーデックの指定を落とし、拡張子を合わせる（`voice-YYYYMMDD-HHmmss.webm` / `.m4a` など）。アップロードは通常の添付と同じ Presign → PUT。
- webm の録音はファイルから長さを読めないことがあるので、計測した録音時間をアップロード時の `duration_seconds` に使う。
- 表示は既存の音声添付（波形風の再生 UI とアプリ全体のプレイヤー）をそのまま使う。

## 下書き

- `draft` テーブル（`user_id` / `channel_id` / `parent_id`（スレッドの親、NULL 可）/ `body` / `updated_at`）。置き場所ごとに 1 件だけ持つ。
  - PostgreSQL の一意制約では NULL 同士が重複扱いにならないため、`parent_id IS NULL` と `IS NOT NULL` の 2 本の部分一意インデックスにする。保存はそれに合わせた `ON CONFLICT ... WHERE` の UPSERT。
- 入力欄は本文を 800ms 待ってから保存し、チャンネルを離れる（入力欄が消える）ときは待たずに保存する。本文が空白だけなら削除する。
- 開き直したときは下書きの取得（取り直しが終わった値）を 1 回だけ入力欄に戻す。読み込み前に打ち始めていたら上書きしない。
- 送信・予約した入力欄は下書きを消す。削除はクライアントが `DeleteDraft` を呼ぶ（メッセージ作成の処理に下書きの都合を持ち込まないため）。
- 下書きは本文だけ。添付と位置情報は下書きに残さない。
- サイドバーのチャンネルには、そのチャンネル（スレッドを含む）に下書きがあれば鉛筆の印を出す。

## 予約送信

- `scheduled_message` テーブル。本文・添付 ID・位置情報・`scheduled_at`・`status`（`scheduled` / `sending` / `sent` / `failed`）・`sent_message_id`・`failure_reason` を持つ。
- 予約するときに、通常の投稿と同じ確認（チャンネルの権限・アーカイブ・返信先・添付が本人の未使用のものか）をする。添付はメッセージに紐付けずに ID だけ持ち、送信時に紐付ける。
- 送信はサーバープロセス内のワーカー（10 秒ごとの ticker）が行う。
  - 期限の来た予約を `UPDATE ... WHERE id IN (SELECT ... FOR UPDATE SKIP LOCKED) RETURNING id` で `sending` にしてから取り出す。サーバーを複数動かしても同じ予約を二重に送らない。
  - 送信は通常の `CreateMessage` を呼ぶ。権限の確認・メンション・リンク・検索インデックスの更新・WebSocket の配信は通常の投稿と同じ経路を通る。
  - 送信時点で権限を失っている・チャンネルがアーカイブされた・添付や返信先がなくなった場合は `failed` にし、その理由を `failure_reason` に残す。それ以外の内部エラーは詳細を出さず「送信に失敗しました」とする。
  - 投稿中にプロセスが落ちた予約は `sending` のまま残る。二重送信を避けるため、自動では送り直さない。
- 「今すぐ送信」は、予約中か失敗した 1 件だけを同じく `sending` にしてから送る。
- 本文と日時の変更は予約中・失敗したものだけでき、失敗したものは予約中に戻る。

## 一覧ビュー

- `/app/$workspaceId/drafts` で「下書き」「予約済み」「送信済み」をタブで切り替える。
  - 下書きは開く（チャンネルかスレッドの入力欄へ）と削除。
  - 予約済みは予約中・送信中・失敗を送信予定の順に並べ、編集（本文と日時）・今すぐ送信・削除ができる。
  - 送信済みは予約から送ったメッセージだけを新しい順に並べ、元の投稿へ移動できる。
- 送信ボタンの横のメニューから「1 時間後」「明日の朝 9:00」「次の月曜 9:00」か、任意の日時（端末のタイムゾーン、分まで）で予約する。
