# メッセージ表示の拡張（メディア・リンク・ピン・リアクション）

issue #14 のバックエンド側の設計判断をまとめる。

## メッセージの組み立て

- メッセージを返すユースケース（一覧・スレッド・作成・編集・検索・ピン・ブックマーク）は、すべて `usecase/message` の `MessageOutputBuilder.Build(ctx, viewerID, messages)` で出力を作る。メンション・リンク・リアクション・添付・ピンを一括で取得するため、どの API でも同じ内容が返る。
- 出力は閲覧者（viewerID）ごとに決まる。いまはメッセージリンクの引用カードだけが閲覧者によって変わる。

## 添付ファイルのメタデータ

- 幅・高さ・再生時間は、アップロード前にクライアントが計測して `PresignUpload` で送る。サーバーは値の範囲だけを検証して保存し、`MessageAttachment.media` で返す。
  - アップロードは署名付き URL でストレージへ直接送るため、サーバーはファイルの中身を持たない。寸法を読むには保存後にストレージから読み直す必要があり、投稿のたびに余計な往復が増える。
  - スマートフォンの写真は EXIF の回転情報でブラウザの表示寸法とファイル上の寸法が入れ替わる。ブラウザが計測した値のほうがレイアウトの予約に合う。
  - 値はレイアウトシフトを防ぐためのヒントであり、誤っていても表示が崩れるだけで安全性には影響しない。
  - ストレージの抽象（`StorageService`）には手を入れていないため、GCS へ移っても影響しない。
- MIME タイプはパラメータを除いて小文字に正規化する。

## 動画のサムネイル

- アップロード時にクライアントで作る。寸法を測るために読み込んだ `<video>` を 1 秒（短い動画は長さの半分）の位置へシークし、canvas に描いて長辺 960px 以下の JPEG にする。
  - サーバーで ffmpeg を使う案は採らなかった。本体は署名付き URL でストレージへ直接送るためサーバーはファイルを持たず、生成のためにダウンロードし直す往復と CPU・メモリの負荷が増える。k8s で動かすときにも ffmpeg 入りのイメージや非同期ジョブの基盤が要る。
  - ブラウザが再生できない形式（Chrome の HEVC など）は切り出せない。その場合はサムネイルなしで投稿し、従来どおり暗い枠を出す。
- `PresignUpload` に `thumbnail`（種類・サイズ・寸法）を付けると、本体と別にサムネイル用の署名付き URL を返す。オブジェクトキーは本体のキーに `-thumbnail` を付けたもの。サムネイルは動画にだけ付けられる。キーと寸法は `attachment` に保存し、添付の削除時にオブジェクトも消す。
- メッセージの `MediaMetadata.thumbnail` に寸法を載せ、画像は `GetDownloadUrl` に `thumbnail: true` を付けて取得する。メッセージに署名付き URL を直接入れないのは、キャッシュや WebSocket で配ったメッセージの URL が期限切れになるため（画像と同じく表示するときに取得する）。
- サムネイルのアップロードは本体と並行して行い、失敗しても本体の投稿は続ける（表示時に読み込めなければ代替表示になる）。
- 表示は、再生前のインラインの枠にサムネイルを敷き、再生を始めたら共有の `<video>` の `poster` にも設定して読み込み中やミニプレイヤーへの移動直後に黒い枠が出ないようにする。`application/octet-stream` や空のときは拡張子から推定する（推定できる種類は実行環境の MIME テーブルに依存する）。

## メッセージリンク

- 同じワークスペースのメッセージを指す URL を「メッセージリンク」として扱う。形式は次のとおりで、ホストは問わない（フロントエンドの配信元が複数あっても動くようにするため）。
  - チャンネルのメッセージ: `/app/{workspaceId}/{channelId}?message={messageId}`
  - スレッド: `/app/{workspaceId}/{channelId}/thread/{threadId}`（親メッセージを指す）。`?message={replyId}` を付けると返信を指す。
- 投稿・編集時に `LinkProcessingService` が URL を判定する。同じワークスペースに実在し、URL のチャンネルと一致するメッセージなら `message_link.linked_message_id` に記録し、OGP は取得しない（自前の SPA を取りに行っても意味がないため）。
- 引用カード（投稿者・チャンネル名・本文の先頭 200 文字・日時）は読み出しのたびに組み立てる。削除済みのメッセージと、閲覧者がチャンネルを参照できないメッセージは展開しない。書き込み時に内容を保存しないのは、閲覧者ごとに権限が違い、引用元の編集・削除も反映したいため。
- WebSocket の `newMessage` / `messageUpdated` は投稿者の権限で組み立てた出力を購読者全員へ送るため、引用カード（`message_preview`）を取り除いて配信する。フロントエンドは `linked_message_id` があって `message_preview` がないリンクについて `MessageService.GetMessagePreview` を呼ぶ。参照できない場合は `NotFound` が返る。

## OGP と YouTube

- 保存済みの OGP は URL ごとに再利用する。タイトルが取れていないものは再取得する。
- `og:image:width` / `og:image:height` があれば画像の寸法も返す。
- YouTube の動画 URL（`watch?v=`・`youtu.be`・`shorts`・`embed`・`live`）は動画 ID を取り出し、動画ページの OGP と microdata（`itemprop="duration"`、投稿者の `itemprop="name"`）からタイトル・サムネイル・チャンネル名・再生時間を読む。外部 API キーは使わない。
  - 同意画面などでタイトルが取れないときは oEmbed（`/oembed`）で補う。oEmbed には再生時間がないため、その場合は再生時間なしになる。
  - サムネイルが取れないときは `i.ytimg.com/vi/{id}/hqdefault.jpg` を使う。
  - 動画ページはメタデータが 700KB 付近にあるため、HTML の読み込み上限を 2MB にしている。

## ピン留めとリアクション

- メッセージには、ピン留めされている場合に `pin`（ピン留めした人と日時）を含める。一覧を取得した時点でラベルを表示できる。
- WebSocket の `pinCreated` には、ラベル表示用に `pinned_by_user` を含める。
- リアクションは押した順（`created_at` 昇順）で返す。メッセージの `reactions` と `ReactionService.ListReactions` の両方にユーザーと日時が含まれるため、ツールチップと一覧モーダルはこれで表示できる。
- WebSocket の `reactionAdded` には `user` と `created_at` を含める。削除のイベントは `user_id` だけを持つ。

## シードデータ

YouTube のリンク、メッセージリンク（参照できるもの・private チャンネルのもの）、ピン留め、多数のリアクションのサンプルを作る。添付ファイルはストレージに実体が必要なため作らない。

## フロントエンド

### グローバルプレイヤー

- 音声・動画の再生は `features/player/mediaPlayer.ts` の 1 つのストアに集約する。`<audio>` と `<video>` はアプリ全体で 1 つずつだけ作り、React の外（モジュールのシングルトン）に置く。画面の再描画やチャンネルの切り替えでは要素が作り直されないため、再生が止まらない。状態は `useSyncExternalStore`（`usePlayerState`）で購読する。
- 動画の要素は「枠」（`VideoSlot`）に差し込んで映す。枠はメッセージ内（inline）とミニプレイヤー（mini）の 2 種類で、元のメッセージが画面に見えていればその枠、見えていなければミニプレイヤーの枠に移す。どちらもなければ画面外の置き場所に移す。DOM から外すとブラウザが一時停止するため、要素は常にどこかに置いておく。
- 元のメッセージが見えているかは `IntersectionObserver` で判定する。見えていないとき（スクロールで外れた・別のチャンネルに移った）にミニプレイヤーを出す。ミニプレイヤーの「元のメッセージへ移動」は、メッセージが描画されていればスクロール、なければ `?message=`（スレッドの返信はスレッドのルート）へ遷移する。
- 置き場所はデスクトップがサイドバー下部（`MiniPlayerSlot`）、モバイルはチャンネルの画面では入力欄の上、タブの画面ではボトムタブの上。共有の `<video>` の枠が 2 つできないよう、`MiniPlayer` は画面幅に合う配置のものだけを描画する。
- 再生する URL は再生を始めるときに `GetDownloadUrl` で取得する。署名付き URL の期限切れで読み込みに失敗したら、1 回だけ取り直して同じ位置から続ける。
- 音声の波形は実際の音量ではなく、添付 ID から決まる見た目だけのもの（ファイル全体をダウンロードして解析するのは重いため）。

### 画像

- 1 枚は幅・高さから 400×300 に収まる枠を計算して予約し、縮めても 140×90 を下回る極端な比率は切り取って「縦長 / 横長 · 全体を表示」を出す。複数枚は 2〜4 枚のグリッドにし、5 枚目以降は 4 枚目に「+N」を重ねる。
- ライトボックスは React Aria の `Modal` で、←→ キー・前後ボタン（モバイルはスワイプとドット）で移動する。縦長（高さが幅の 2.2 倍超）はスクロールで見せる。
- 表示用の URL は添付ごとに `useQuery(GetDownloadUrl)` で取得し、有効期限より短い 4 分だけ使い回す。
- アップロード時に `measureMedia` でブラウザに読ませて寸法・再生時間を計測し、`PresignUpload` に送る。計測できなくてもアップロードは続ける。
- 画像ビューアや動画の背景は表示モードによらず暗くするため、`media` / `media-fg` トークンを追加した。

### リンク・本文・リアクション

- `LinkPreviewEmbed` は、メッセージリンク → 引用カード、YouTube → 動画カード（iframe は使わず、押すと YouTube を新しいタブで開く）、それ以外 → OGP の順に振り分ける。引用が付いていないメッセージリンク（WebSocket で届いたもの）は `GetMessagePreview` を取得し、`NotFound` なら何も出さない。
- 12 行を超えるコードブロックは 220px で折りたたみ、「すべて表示（n 行）」で広げる。
- 絵文字だけ（空白を除いて 8 文字以内、書記素で数える）の投稿は 34px で表示する。
- リアクションは 10 種類を超える分を「+N」にまとめる。ツールチップには押した人（自分は「あなた」、5 人以上は 3 人と残りの人数）を出し、右クリックかメッセージのメニューで一覧のダイアログを開く。一覧は `Message.reactions` の `created_at` を新しい順に並べるので、追加の API は呼ばない。
- ピン留めは `Message.pin` で判定し、WebSocket の `pinCreated` / `pinDeleted` でタイムラインの `pin` を更新する。

## 開発用のローカルストレージ

`STORAGE_DRIVER=local` にすると、添付ファイルを `LOCAL_STORAGE_DIR`（既定は `tmp/storage`）に保存する `storage/local` の実装を使う（既定は `wasabi`）。

- `StorageService` の別実装で、S3 と同じく署名付き URL（HMAC、期限付き）を発行し、バックエンドの `/storage/*` で PUT / GET を受ける。フロントエンドはどちらのドライバでも同じ手順でアップロード・表示できる。
- URL のホストは `PUBLIC_BASE_URL`（既定は `http://localhost:$PORT`）。署名の鍵は `JWT_SECRET` を流用する。
- GCS など別のストレージを足すときも、`StorageService` と `StorageConfig` を実装してレジストリで切り替えればよい。
