# 検索・メンション一覧・スレッド一覧の設計

## メッセージ検索

### リクエストの形

- `from:` や `in:` などの修飾子はクライアントで解析し、`SearchWorkspaceRequest.message_filter`（構造化したフィルタ）とキーワード `query` に分けて送る。サーバーは修飾子の文字列を解釈しない。
  - 理由: チップ UI と入力欄の双方向の反映や、React Native との共有をクライアント側のパーサーでまとめて扱うため。
- `during:today|week|month` はクライアントで `after` / `before` の日時に変換する。タイムゾーンの解釈をサーバーに持ち込まないため。
- フィルタの条件はすべて AND。`from_user_ids` / `channel_ids` はそれぞれの中で OR、`has` は指定したものをすべて満たすもの。
- キーワードが空でも、絞り込み条件（返信を除く以外）が 1 つでもあれば検索できる。チャンネル・ユーザー・グループはキーワードがあるときだけ検索する。

### 各条件の定義

| 条件 | 定義 |
| --- | --- |
| キーワード | 空白（全角を含む）で区切った語をすべて、本文か添付ファイル名に含む。大文字小文字は区別しない |
| `has:image` / `has:video` | MIME タイプが `image/` / `video/` の添付がある |
| `has:file` | 画像・動画以外の添付がある |
| `has:link` | OGP を取得したリンクがあるか、本文に `http://` / `https://` を含む |
| `is:pinned` | ピン留めされている |
| `is:thread` | スレッドの返信、または返信のある親 |
| 自分宛て | 自分へのメンション、所属グループへのメンション、参加しているチャンネルでの `@channel` / `@here` |
| 下階層を含む | チャンネル名が `<親の名前>/` で始まるチャンネルも対象にする |

検索対象は、ワークスペース内の公開チャンネルと、参加している非公開チャンネル（DM を含む）のメッセージ。削除済みは含めない。

### 実装方式（PostgreSQL）

- `ILIKE '%語%'` による部分一致を使う。
  - PostgreSQL 標準の全文検索（`to_tsvector`）は日本語の単語分割ができず、日本語では使えない。
  - `pg_trgm` の GIN インデックスは 3 文字未満の語（日本語では「設計」のような 2 文字の語が多い）に効かず、ロケールによっては日本語の文字をトライグラムに含めない。
  - 現状のデータ量では全件走査で十分なため、インデックスは追加しない。データが増えたら、`pg_trgm` のインデックスか、日本語に対応した検索（PGroonga や外部の検索エンジン）を検討する。
- `@channel` / `@here` はメンションのテーブルに記録していないため、本文に対する正規表現で判定する。

### 関連度順

次の順で並べる。

1. 語が 2 つ以上のとき、語を空白でつないだ句をそのまま含むもの
2. 語の出現回数の合計が多いもの
3. 新しいもの

TF-IDF のような重み付けはしない。ユーザーが結果の順序を予想しやすいことを優先した。

### ハイライト

結果の各メッセージに、本文中で語に一致した範囲（`highlights`）を返す。オフセットは JavaScript の文字列と同じ UTF-16 のコード単位で、重なる範囲はまとめてある。抜粋はクライアントで範囲の周辺を切り出して作る。

## メンション一覧（`MentionService.ListMentions`）

- 自分宛て（検索の「自分宛て」と同じ定義）のメッセージを、新しい順にカーソルでページングして返す。自分の投稿は含めない。
- 新着でずれないよう、オフセットではなく `(created_at, id)` のカーソルを使う。
- 既読・未読は持たない。通知のバッジなどは既存の未読数の仕組みで扱う。

## スレッド一覧（`ThreadService.ListParticipatingThreads`）

- 最終アクティビティ（削除されていない最新の返信、なければ親の投稿日時）の新しい順に並べ、カーソルも同じ値を使う。
- 各スレッドに、ユーザー情報などを含む親メッセージと、最新の返信 2 件（`latest_replies`）を返す。一覧のカードにそのまま表示できるようにするため。
- 未読数には自分の返信を数えない。
- 一覧からの返信は既存の `MessageService.CreateMessage`（`parent_id` を指定）を使う。返信した結果はレスポンスの `message` を `latest_replies` に追加するか、一覧を再取得して反映する。
