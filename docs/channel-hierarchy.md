# 階層チャンネル・スター・関連リンク・個人メモの設計

issue #13 のバックエンドで決めたことをまとめる。

## 階層の表現

- `channel.name` にスラッシュ区切りのフルパス（`dev/frontend/web`）を保存し、あわせて直近の親を `parent_id` で持つ。
  - フルパスを持つことで、ワークスペース内の名前の一意制約をそのまま階層全体の一意性に使え、子孫の取得もパスの前方一致 1 回で済む。
  - `parent_id` はツリーの組み立てをクライアントで簡単にするために持つ。フロントエンドは `parent_id` でつなぐか、`name` の末尾のセグメントを表示名に使う。
- すべての階層が実在するチャンネルになる。作成時に存在しない祖先は自動で作る。
  - 自動で作る祖先は、作成するチャンネルと同じ公開範囲にし、作成者を参加させる。非公開チャンネルの作成をきっかけに公開チャンネルが増えないようにするため。
  - 既存の祖先が閲覧できない非公開チャンネルの場合は作成できない。
- 名前の変更で変えられるのは末尾のセグメントだけ（別の親への移動は扱わない）。変更すると子孫のパスも同じトランザクションで付け替える。
- 子孫を持つチャンネルは削除できない。先に子孫を削除する。
- DM・グループ DM は階層の対象外。

## 名前の制約

- セグメントに使えるのは Unicode の文字・数字・`-`・`_`。英字は小文字にそろえる（`Dev` と `dev` を別チャンネルにしない）。
- 1 セグメント 32 文字まで、深さは 4 階層まで。サイドバーでの表示幅とツリーの読みやすさから決めた。
- 形式は proto（protovalidate の正規表現）とドメイン（`entity.NormalizeChannelPath`）の両方で検証する。小文字化はドメイン側で行う。

## チャンネル一覧

- `ListChannels` は参加中のチャンネルに加えて、ツリーを組み立てるために閲覧できる未参加の祖先チャンネルも返す。`is_member` で区別する（未参加の祖先の未読数は 0）。
- 並びは名前（フルパス）順。

## 親チャンネルの集約表示

- `ListMessages` / `ListMessagesWithThread` に `include_descendants` を指定すると、閲覧できる子孫チャンネル（公開チャンネルと参加中の非公開チャンネル）のメッセージを時系列でまとめて返す。各メッセージの `channel_id` でどのチャンネルのものかを表示する。
- 未参加の公開子孫チャンネルも含める（閲覧権限は通常のチャンネル表示と同じ）。チップの名前がチャンネル一覧にない場合は `GetChannel` で取得する。
- 新着の受信には、子孫チャンネルも WebSocket で `joinChannel` する必要がある。

## 集約表示中の既読

- 表示した子孫チャンネルも既読にする。`UpdateReadState` に `include_descendants` を指定すると、親と閲覧できる子孫をまとめて `last_read_at` まで既読にする。
- 子孫の既読位置は進めるだけで戻さない（子孫を個別に開いてより新しい位置まで読んでいる場合があるため）。
- 集約表示で見えていたメッセージは読んだとみなすのが自然で、折りたたんだ親に出す子孫の未読合計とも整合するため、この方針にした。

## スター

- `channel_star`（ユーザー × チャンネル）で持つ。DM・グループ DM もチャンネルなので同じテーブルを使う。
- `SetChannelStarred` で付け外しし、`ListChannels` / `GetChannel` / `ListDirectMessages` が `is_starred` を返す。閲覧できないチャンネルには付けられない。

## ミュート

- スターと同じ構成で `channel_mute`（ユーザー × チャンネル）に持つ。ユーザーごとの状態で、チャンネル・DM・グループ DM 共通。チャンネル設定の列にしないのは、ミュートが個人の設定でありメンバー以外（未参加の祖先チャンネル）にも付けられるようにするため。
- `SetChannelMuted` で切り替え、`ListChannels` / `GetChannel` / `ListDirectMessages` が `is_muted` を返す。権限はスターと同じく閲覧できること。
- サーバーはミュートでも未読数・メンション・WebSocket 配信を変えない。通知や未読バッジの抑制はクライアントが `is_muted` を見て行う（ミュート中でもメンションだけは目立たせる、といった表示の方針をクライアント側で決められるようにするため）。

## DM の未読数

- `ListDirectMessages` がチャンネルと同じ `ReadStateRepository` の一括取得で `unread_count` / `has_mention` を返す。DM も既読管理はチャンネルと同じ `read_state` を使う。

## 関連リンク

- `channel_link`（タイトル・URL・並び順）で持ち、`ChannelLinkService` で一覧・追加・編集・削除・並び替えを行う。並び替えはチャンネルの全リンクの ID を新しい順番で渡す。
- 編集できるのはチャンネルの参加者とワークスペースの管理者。判定は `channellink` ユースケースの `canEdit` 1 か所にまとめてあり、権限設定（#16）の導入時にここを差し替える。`ListChannelLinks` は `can_edit` を返すので、フロントエンドは編集 UI の出し分けに使う。

## 10 人を超える DM

- グループ DM は自分を含めて 10 人まで。
- それを超える場合は `CreateChannel` に `is_private: true` と `member_ids` を指定して非公開チャンネルを作る。非公開チャンネルはゲスト以外のメンバーなら作成できる（公開チャンネルは従来どおり管理者のみ）。作成権限の判定は `channel` ユースケースの `ensureCanCreateChannel` にまとめてある。

## ニックネームとメモ

- `user_note`（持ち主 × 対象ユーザー）で持つ。ワークスペースをまたいで共通。
- `GetUserNote` / `UpdateUserNote` で取得・更新する。ニックネームとメモを両方空にすると削除する。
- ニックネームはどこでも表示に使うため、`ListMembers` が各メンバーの `nickname` を返す。フロントエンドはこれを引いて表示名を置き換える。

## 閲覧中表示

WebSocket の `viewChannel` / `channelViewers` で配信する。詳細は [websocket/backend.md](./websocket/backend.md#閲覧中表示プレゼンス) を参照。
