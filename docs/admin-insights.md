# 管理画面・権限設定・インサイトの設計

issue #16 のバックエンドで決めたことをまとめます。

## 監査ログ（`audit_log`）

- 記録する操作: ログイン / ログインの失敗 / ロールの変更 / メンバーの停止・再開 / チャンネルの作成・削除・アーカイブ・アーカイブ解除 / 権限設定の変更 / 監査ログの CSV の書き出し。
- 実行者・操作・対象（種類、ID、記録時点の名前）・詳細（`map<string,string>`）・IP アドレス・User-Agent・日時を持つ。対象や実行者が削除されてもログは残したいので外部キーは張らず、対象の名前は記録時点のものを保存する。
- IP アドレスと User-Agent は Connect の interceptor が context に載せ、ユースケースの `audit.Recorder` が読み取る。ロードバランサーの配下を想定し `X-Forwarded-For` の先頭を優先する（信頼できるプロキシの設定は本番環境の構成が決まってから行う）。
- 記録は操作のあとに行い、記録に失敗しても元の操作は取り消さずエラーログに残す（ベストエフォート）。
- ログインはワークスペースに属さないため、ユーザーが参加している全ワークスペースに同じ記録を書く。ログインの失敗は本人の操作とは限らないので実行者を空にし、対象ユーザーとして残す。存在しないメールアドレスへのログイン失敗はどのワークスペースにも記録しない。
- 一覧はページトークン（カーソル）でページングし、総件数は返さない（下の「保存先」を参照）。
- CSV はサーバーで作る。ページングを気にせず絞り込み結果をまとめて書き出せ、書き出しを監査ログに正しい件数で残せ、数式インジェクション対策（先頭が `= + - @` のセルに `'` を付ける）を一箇所にまとめられるため。Excel 向けに BOM を付け、1 回 10,000 件までとする。

### 保存先

将来は監査ログを NoSQL（Firestore / Bigtable など Google Cloud のもの）に移せるようにしておく。現状の実装は PostgreSQL（ent）のまま。

- 読み書きは `AuditLogRepository`（`Create` / `List`）だけを通す。ユースケースは SQL を知らず、実行者の名前は `UserRepository.FindByIDs` でまとめて引く（JOIN しない）。
- `List` の条件はワークスペース・実行者・操作の種類・期間（開始以上・終了未満）と、新しい順の件数指定だけにする。Firestore の複合インデックス（`workspace_id` + 条件 + `created_at` 降順）や、Bigtable の行キー（ワークスペース + 逆順の時刻）で素直に表せる範囲にとどめるため。
- 総件数とオフセットは使わない。NoSQL では件数の集計やオフセットが高くつく（Bigtable ではできない）ため。続きはリポジトリが発行する不透明なページトークンで取る。PostgreSQL の実装では最後の行の `(created_at, id)` を入れている。
- 記録は呼び出し元のトランザクションに参加させない。保存先が別の DB になっても振る舞いを変えないため。もともと操作のあとにベストエフォートで記録している。
- 対象や実行者への外部キーは張らない（上記）ので、ほかのテーブルとの整合性に依存しない。

## 権限設定（`workspace_permission`）

- ロール（admin / member / guest）× 操作の組み合わせのうち、既定値から変更されたものだけを保存する。オーナーは常にすべて許可。
- 既定値: 管理者はすべて許可。メンバーは公開・非公開チャンネルの作成、関連リンクの編集、ピン留めを許可。ゲストはすべて不可。
- 判定はドメインサービス `PermissionService.Ensure` に集約し、各ユースケースから呼ぶ。停止中のメンバーはここで拒否される。
  - チャンネルの作成 → 公開 / 非公開それぞれの権限
  - メンバーの招待 → 招待の作成・一覧・取り消し（`InvitationService`、docs/auth.md）。管理者として招待できるのは管理者だけ
  - メッセージのピン留め・解除
  - 他人のメッセージの削除
  - 関連リンクの追加・編集・削除・並び替え（これまでの「チャンネルの参加者か管理者」から置き換えた）
- ユーザーグループの作成・編集・削除・メンバーの追加削除（本人が抜ける場合を除く）は権限設定の対象外で、常に owner / admin だけができる。グループへのメンションは全員に通知が飛ぶため、誰でも作れる状態にしないことにした。
- 監査ログの CSV の書き出しは管理画面の API なので owner / admin だけができる（専用の権限は設けない）。
- 以前あった「データのエクスポート」「外部アプリの追加」の権限は、機能ごと削除した（外部連携はチャンネル単位の Webhook で扱う）。
- 管理者が自分たちの権限を広げられないよう、管理者の列はオーナーだけが変更できる。
- 権限の一覧はボタンの出し分けに使うためメンバー全員が参照できる。

## メンバーの停止

- `workspace_member.suspended_at` で表す。ワークスペース単位の停止で、アカウント自体は他のワークスペースで使える。
- 停止するとそのユーザーのリフレッシュトークン（セッション）をすべて失効させる。アクセストークンは短命な JWT のため即時には失効しないが、`WorkspaceRepository.FindMember` が停止中のメンバーを返さないので、そのワークスペースの API（非公開チャンネルを含む）は直ちに拒否される。
- 投稿は残す。停止中も管理画面のメンバー一覧には表示する。
- セッションはログイン単位で持つようにし、リフレッシュでは新しいセッションを作らずトークンだけ差し替える。これによりセッションの作成日時と IP・User-Agent を「最終ログイン」として使える。

## インサイト

- 集計は問い合わせのたびに SQL で計算する（日次集計テーブルは作らない）。現状のデータ量では十分速く、集計の定義を変えても再計算が不要なため。遅くなった場合は `InsightRepository` の実装を日次集計テーブルに差し替える。
- KPI は直近 30 日と、その前の 30 日を比較する。
  - アクティブなメンバー: 期間内に投稿かリアクションをした人（既読は最新の時刻しか残らず過去の期間と比較できないため含めない）
  - アクティブ率: アクティブなメンバー / 期間の終わり時点のメンバー数（停止中を除く）
  - メッセージ数: 削除されていないメッセージ（スレッドの返信、DM を含む）
  - ストレージ: 添付済みのファイルの合計サイズ（期間の終わり時点）
- 日付・曜日・時刻はリクエストで受け取った IANA タイムゾーン（ブラウザのタイムゾーン）で区切る。サーバーのイメージに tzdata が無くても動くよう `time/tzdata` を埋め込んでいる。
- ヒートマップは直近 4 週の合計を返し、平均は画面側で計算する。
- 個人を特定できる数値は返さない。チャンネル別の集計から DM を除き、メンバーには参加していない非公開チャンネルを返さない（管理者はすべて見られる）。例外は本人の投稿数だけ。
- メンバーごとの内訳（直近 30 日の投稿数、アップロードしたファイルの合計、最後の投稿日時）は管理画面のメンバー一覧（owner / admin のみ）で返す。

## チャンネルのアーカイブ

- `channel.archived_at` で表す。作成者かワークスペースの管理者が実行でき、DM はアーカイブできない。アーカイブ中は投稿できない（閲覧は可能）。

## 画面（フロントエンド）

- ルートは `/app/$workspaceId/insights` と `/app/$workspaceId/admin`。管理画面のタブ（概要 / メンバー / 権限 / 監査ログ）は子ルートにせず search param の `tab` で持つ（タブごとにローダーを分ける必要がなく、リンクで直接開ける）。
- 管理画面のルートは `beforeLoad` で `GetWorkspace` の自分のロールを確かめ、owner / admin 以外はインサイトへリダイレクトする。表示の出し分けにすぎず、拒否は API 側で行う。
- 画面は `features/admin`・`features/insights` に置き、ページは `pages/AdminPage.tsx`・`pages/InsightsPage.tsx`。
- グラフはライブラリを入れず、HTML と CSS で自作した（縦棒・横棒・ヒートマップ）。必要な形が少なく、色をトークン（CSS 変数）だけで塗れ、ダークモードの切り替えも追加の処理が要らないため。React Native に移すときは同じデータ整形（`features/insights/utils/chart.ts`）を使い、描画だけ作り直す。
  - 色はアクセントの 1 色だけ。ヒートマップの濃淡は `color-mix` でアクセントと面の色を混ぜて作るので、ダークでは件数が多いほど明るくなる。
  - ホバーで値を出すが、値はツールチップだけに置かず、すべてのカードに「表で表示」の切り替えを付ける。
  - 今日の棒は集計途中なので薄く描く。
- 個人を特定できる数値はインサイトに出さない（「あなたの投稿」だけ本人の数値）。メンバーごとの投稿数・ストレージは管理画面の概要とメンバーの表にだけ出す。
- 監査ログの絞り込み（実行者・操作の種類・期間）は search params（`actor` / `action` / `period` / `since` / `until`）に持ち、リンクで共有・再現できるようにする。タブを切り替えても保持する。
- 期間はプリセット（24 時間 / 7 日 / 30 日 / 90 日 / すべて）と「日時を指定」。日時の指定は開始・終了を分単位で入れる（終了は含まない）。入力はネイティブの `datetime-local` を使い、URL にはブラウザのタイムゾーンでの `YYYY-MM-DDTHH:mm` を入れる。依存を増やさず、モバイルでは OS のピッカーが使えるため。
- 一覧は総件数を持たないので、ページ番号ではなく「さらに読み込む」で続きを足していく（`useInfiniteQuery` + `page_token`）。
- 2 段階認証は未実装で常に「未設定」と出るだけだったため、メンバーの列と概要の数値から外した。
- CSV はサーバーが返した文字列を Blob にして保存させる（書き出し自体が監査ログに残るので、書き出し後に一覧を取り直す）。
- メンバーのロールは管理者 / メンバー / ゲストから選べるよう `UpdateMemberRole` でゲストも受け付けるようにした。オーナーの行と自分の行、停止中のメンバーはロールを変えられない。
